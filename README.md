# ColdChain-Exposure-Watch

スーパーマーケットや冷蔵倉庫で使われる**冷蔵設備の管理画面**が、インターネットからどれだけ見える状態にあるかを、Shodan の集計値だけで定点観測するためのスクリプト集です。

2026年10〜11月、欧州を中心に、ネットにつながった冷蔵設備が遠隔操作され、庫内の温度を上げられる事案が相次ぎました。このリポジトリは、その調査記事で使ったスクリプトを公開するものです。

- 前報：[冷蔵庫がサイバー攻撃されたらしいので、調べてみた](https://qiita.com/01rabbit/items/5ae5d9123657428431d0)（2026-11-05）
- 続報：[冷蔵庫がサイバー攻撃された件に続きがあったので調べてみた](https://qiita.com/01rabbit/items/843e3fb563a74cd1a9d9)（2026-11-07）

> [!IMPORTANT]
> このツールは**件数を数えるだけ**です。IPアドレスの一覧を取得したり、機器に接続したり、ログインを試したりする機能はありません。追加しないでください（[してはいけないこと](#してはいけないこと)を参照）。

## できること

| スクリプト | 何をするか | 使う場面 |
|---|---|---|
| `exposure_count.py` | 冷蔵設備の管理画面（Danfoss StoreView、Copeland/Dixell XWEB、CAREL pCOWeb、Eliwell Televis Go）の件数を、期間・国・製品の系統ごとに数える | 露出が増えたか減ったかを、定期的に測る |
| `surge_breakdown.py` | 件数が急に増えた国について、増えた分が「どこの回線に」「どのポートで」「どんな画面で」出ているかの偏りを調べる | 急増が実機なのか、おとり（ハニーポット）なのかを見分ける |
| `sanitize_for_publication.py` | 計測結果から、事業者名・ASN・証明書の情報・HTMLハッシュなどを取り除く | 結果を公開する前に必ず通す |

記事で使った計測データ（公開用に加工済み）は [`data/`](data/) にあります。

どれも Shodan の **count API**（`/shodan/host/count`）だけを使います。count API は検索クレジットを消費しません。

## 必要なもの

- Python 3.8 以上
- [Shodan](https://www.shodan.io/) のアカウントと API キー
  - 契約プランによって、使えるファセット（集計の切り口）が異なる場合があります。使えないファセットは自動的に外して計測を続けます。

## 準備

```bash
git clone https://github.com/01rabbit/ColdChain-Exposure-Watch.git
cd ColdChain-Exposure-Watch

# 仮想環境を作ってライブラリを入れる
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

API キーは、**シェルの履歴に残らない方法**で設定してください。

```bash
read -s SHODAN_API_KEY && export SHODAN_API_KEY
```

> [!WARNING]
> `SHODAN_API_KEY=xxxx` のように直接打つと、キーがシェルの履歴（`~/.zsh_history` など）に残ります。また、この書き方を単独の行で実行しても、次に起動する `python3` にはキーが渡りません。

## 使い方

### 1. 露出件数を測る（`exposure_count.py`）

```bash
python3 exposure_count.py
```

1〜2分ほどで、`counts_YYYYmmdd_HHMMSS.json` が作られます。実行中は、クエリごとの件数が画面に表示されます。

| オプション | 意味 | 既定値 |
|---|---|---|
| `--since DD/MM/YYYY` | この日以降の件数も数える。複数指定できる | `01/11/2026` と `04/11/2026`（欧州第2波と、EU・米国の警告の日） |
| `-o ファイル名` | 出力先 | `counts_YYYYmmdd_HHMMSS.json` |

```bash
# 例：11月10日以降の件数も数え、ファイル名を指定する
python3 exposure_count.py --since 10/11/2026 -o counts_1110.json
```

**定点観測のコツ**：1週間おきなど、間隔を決めて実行し、毎回の結果を残してください。比較には、ファイル内の `*_r7`（直近7日）・`*_r16`（直近16日）と、TLS の件数（`*_ssl_r16`）を使います。

### 2. 急増の内訳を調べる（`surge_breakdown.py`）

`exposure_count.py` の結果で、特定の国だけ件数が急に増えていたら、こちらで内訳を調べます。

```bash
python3 surge_breakdown.py --countries NL,HK --controls FR,US --split-date 04/11/2026
```

| オプション | 意味 | 既定値 |
|---|---|---|
| `--countries` | 急増した国（国コード、カンマ区切り） | `NL,CN,HK,LV,SG` |
| `--controls` | 比較のための国 | `FR,US` |
| `--split-date` | この日の前後で比べる | `04/11/2026` |
| `-o ファイル名` | 出力先 | `breakdown_YYYYmmdd_HHMMSS.json` |

画面には、各クエリの件数と「**上位3つの割合**」が表示されます。事業者・ASN・ポート・HTMLのそれぞれで、上位3つの値が全体の何割を占めるかを示します。1 に近いほど、少数に集中しています。

特定の HTML ハッシュの件数も数えたい場合は、環境変数 `SV_HTML_HASH` にその値を設定してください。

### 3. 公開用に加工する（`sanitize_for_publication.py`）

```bash
python3 sanitize_for_publication.py counts_20261107_094941.json
# → counts_20261107_094941_public.json ができる
```

## 結果の読み方

### 件数は「台数」ではない

数えているのは、Shodan の検索に一致した**サービス（バナー）の件数**です。

- 1台の機器が複数のポートで応答すれば、複数件になります。
- IPアドレスが変わる回線では、同じ機器が別の件として数えられることがあります。
- 露出していることは、脆弱であることや、侵害されたことを意味しません。

### おとりが混ざる

事案が報道されると、研究者などが実機の画面を真似た**おとり（ハニーポット）**を設置することがあります。2026年11月4日以降には、StoreView の件数が2日で2.6倍に増えましたが、その大半はおとりと見られるものでした（続報の3章）。

おとりの典型的な特徴は次の四つです。`surge_breakdown.py` の結果で確かめてください。

| 特徴 | おとりらしい | 実機らしい |
|---|---|---|
| 回線（事業者・ASN） | 1社か少数のホスティング事業者に集中 | 各国の通信事業者に分散 |
| ポート | 多数のポートに1件ずつ（11、13、15…） | 80・443・8080 などの定番 |
| 画面（HTML） | ほぼ全件が同じ1種類 | 複数の版が混在 |
| TLS | ほとんどない | 一定数ある |

> [!NOTE]
> おとりは実機と**同じ HTML** を返すため、HTML ハッシュだけでは見分けられません。四つを組み合わせて判断してください。それでも判定は推定であり、断定はできません。

### 期間の比べ方

このツールは「実行日から数えた直近7日・16日」で比較します。`after:29/10/2026` のように日付を固定すると、後日実行したときに期間が延びてしまうからです。また、Shodan は同じ IP・ポートについて最新の観測だけを保持するため、過去の期間の件数は時間がたつと減っていきます。

### おとりの影響を受けにくい指標

露出の推移を追うときは、件数そのものより、**TLS を使うサービスの件数**（`xweb_ssl_r16`・`sv_ssl_r16`）を併せて見ることをお勧めします。急増したおとりのほとんどは TLS を使っていませんでした。

## 記事の計測データ

続報の計測（2026-11-07）の結果を、事業者名などを伏せた形で [`data/`](data/) に置いています。ファイルの説明と、記事の計測と現在のスクリプトとの違いは、[data/README.md](data/README.md) を参照してください。

## 結果を公開するとき

計測結果の JSON には、**特定の店舗や事業者を推定できる情報**が含まれます。たとえば、証明書のホスト名に店舗名が入っていたり、事業者名の一覧に中小企業の名前が出てきたりします。

結果を公開するときは、**必ず `sanitize_for_publication.py` を通した `_public.json` だけ**を使ってください。`.gitignore` は、公開版以外の結果ファイルをコミットしない設定にしてあります。

また、おとりの運用者を特定させないよう、急増分の事業者名や ASN を記事などに書かないことをお勧めします。

## してはいけないこと

- **IPアドレスの一覧を取得して機器に接続する**、**ログインを試す**、**設定を変える**といった使い方はしないでください。他人の機器に無断でログインすることは、日本では不正アクセス禁止法に触れるおそれがあります。
- このツールに、検索 API（`/shodan/host/search`）で IP アドレスを取得する機能を追加しないでください。
- 計測結果の生データを公開しないでください（[結果を公開するとき](#結果を公開するとき)）。
- Shodan の利用規約を守ってください。取得したデータの再配布の可否は、ご自身で利用規約を確認してください。

自分が管理する機器が露出していないかを確かめたい場合は、このツールではなく、その機器の保守事業者やメーカーに相談するか、国の CSIRT（日本では JPCERT/CC）の助言に従ってください。

## 既知の制約

- 検索条件は、ページのタイトル（`http.title`）で製品を判別しています。タイトルを変えている機器や、ほかの製品で同じタイトルを使うものは、正しく数えられません。
- `-org:"iiNet Connect Pty Ltd"` は、前報の調査で見つかった大量の疑わしい応答を除くための条件です。状況が変われば不要になる可能性があります。
- Shodan の `cloud`・`honeypot` タグは完全な判定ではありません。新しく設置されたおとりには、しばらくタグが付かないことがあります。
- 記事の計測（2026-11-07）では、タグの件数を `(tag:honeypot OR tag:cloud)` で数えようとして Shodan に受け付けられませんでした。このリポジトリでは、タグごとに分けて数えるよう修正しています。
